Web UI for the STL to 3MF converter

A local web page that does what converter/stl_to_3mf.py does today: drop STL files, pick material, profile, temperatures, layer height and supports, check the part, and download a Creality Print project (.3mf) and, optionally, sliced G-code with the real print time.

1. Goals and scope

In scope

  • Every option the command line has today: material, profile, first-layer and other nozzle temperatures, bed temperature, layer height, supports, and free --set KEY=VALUE settings.
  • Several STL files at once, one plate each (up to 36), as the converter already does.
  • Mesh checks shown before converting: size, volume, watertight, fits the 220 x 220 x 250 mm bed, and "this part is tilted", the problem behind the failed foot-nap prints.
  • Optional slicing with the Creality Print command line, so the page shows the real print time, filament, layer count, and a per-layer preview.
  • Every file is saved in the repository folders by the existing rules: uploaded STL in stl/, project in 3mf/, G-code in gcode/. The page also offers them as downloads.

Out of scope (first version)

  • Rotating, scaling or arranging parts. The converter never does this; the UI only warns.
  • Sending G-code to the printer. Possible later (the Moonraker upload in the matw.pl article), but it needs a printer on the network and a confirmation step.
  • Accounts or a public server. Files are kept in the repository folders (section 8), not in the browser.
  • Editing profiles in the page. Profiles stay JSON files in converter/profiles/.

Principle: the web UI is a thin layer over the existing converter. It calls the same convert() with the same arguments, so a file made in the page is byte-identical to one made with the same options on the command line.

2. User flow

One page, three steps shown in a stepper. Steps can be revisited; nothing is lost when going back.

1 · Add filesDrop or pick STL files (or a folder). Each is checked at once: size, watertight, fits, tilted.
→
2 · SettingsMaterial, profile, temperatures, layer height, supports. Advanced settings are folded away.
→
3 · Convert"Convert" makes the 3MF in about a second. "Convert & slice" also runs Creality Print.
→
ResultPrint time, filament, layer preview, settings check, download buttons.

Keyboard: Ctrl/⌘ O add files · Ctrl/⌘ Enter convert · Ctrl/⌘ Shift Enter convert & slice · Ctrl/⌘ S download · ? shortcut list. Keyboard shortcuts are a must-have for developer tools in the design rules.

  • 3D view of the bed with the part as it will be placed.
  • "Top" shows the footprint; "Layers" appears after slicing.

  • Choosing a profile fills in its values; edited fields get a "changed" dot and a reset link.
  • Advanced settings stay folded until needed.
  • Values are validated when a field loses focus, not on every keystroke.

8. Architecture and API

Pieces

  • Server: a small Python app in a new web/ folder that imports converter/src directly. Recommended: FastAPI + Uvicorn (two packages, adds file-upload handling and request validation). Run with .venv/bin/python web/app.py, listening on 127.0.0.1:8000 only.
  • Page: one HTML file with plain CSS and a small amount of JavaScript, no build step. The 3D view uses three.js with its STL loader, copied into web/static/vendor/ so the page works offline.
  • Slicing: runs the Creality Print command line in a single worker, one job at a time, with a timeout. Disabled when the app is not installed or its window is open.
  • Files: saved in this repository's folders, following the rules in docs/repo-rules.md, so the page and the command line leave the same files in the same places (details below).

Endpoints

CallPurpose
GET /api/libraryWhat is already in stl/, 3mf/, gcode/, with sizes and dates
GET /api/optionsProfiles, materials, limits, preset ranges, slicer available or not
POST /api/filesUpload STL; returns size, volume, watertight, fits, tilt, bed contact, a mesh URL for the 3D view
POST /api/convertFiles + options → 3MF; same arguments as the command line
POST /api/sliceStart slicing a converted project; returns a job id
GET /api/jobs/{id}Progress, then time, filament, layers, settings check
GET /api/jobs/{id}/layersToolpaths per layer for the preview (compact JSON)
GET /api/download/…Send a saved file from stl/, 3mf/ or gcode/ to the browser

Where files are saved

The page follows the folder rules already set for the command line. Paths are relative to the repository root.

FileSaved toNameWhen
Uploaded STLstl/original file name; a folder upload keeps its folder name, e.g. stl/ecs_4970054/40_08_1x.stlon upload, before any check
Project3mf/the converter's default name, <stl name>_claude_ender3[_<material>]<profile suffix>.3mf; several files use the folder name or <first>_and_<n>_moreon "Convert"
Sliced G-codegcode/same name as the project, .gcodeon "Convert & slice"
Slicer work filesscratch folder outside the repositorydeleted after the G-code is copiedwhile slicing
  • Same name, different file: an STL that already exists in stl/ with other contents is not overwritten silently. The page asks: replace, or keep both (name (2).stl). The same applies to 3mf/ and gcode/.
  • Settings that change the result (custom layer height, supports, --set values) are added to the name, e.g. …_hf_fast_0.16_support.3mf, so variants do not overwrite each other. The command line gets the same naming, so both stay identical.
  • Git: stl/, 3mf/ and gcode/ stay git-ignored, so nothing the page saves is committed by accident.
  • Recent files: the files column lists what is already in stl/, so a model uploaded yesterday can be converted again without uploading it.
  • Only these three folders are written. File names are cleaned (no .., no folder separators) so an upload cannot write outside them.

Changes to existing code

  • convert() gets a small result object (sizes, warnings, output path) instead of only printing, so the server and the command line report the same things. Command-line output stays the same.
  • Default output names add the settings that change the result (custom layer height, supports, --set values), for the command line and the page alike. Plain runs keep today's names.
  • New converter/src/inspect.py: mesh checks the page shows before converting, including tilt and bed-contact area.
  • New converter/src/slicer.py: finds the Creality Print executable per OS, runs --cli --slice, and reads time, filament and layers from the G-code header. The command line can use it too (--slice option).
  • New converter/src/gcode.py: the layer parser already used to check the foot-nap prints, moved out of the scratch folder.

9. Phases

Phase 1
~1 day
Converter as a library. convert() returns a result; add inspect.py, slicer.py, gcode.py; add a --slice option to the command line. Check: the Benchy outputs stay byte-identical apart from dates.
Phase 2
~1 day
Server. FastAPI app with the endpoints above, saving into stl/, 3mf/, gcode/, upload limits, single slicing worker. Check: convert and slice the foot-nap file through the API and compare with the command-line output.
Phase 3
~2 days
Page. Files column, settings column, action bar, result screen, all states from section 5. Thumbnail images first; the 3D view comes in phase 4.
Phase 4
~1–2 days
Previews. three.js part view on the bed; layer view from G-code with a slider and keyboard control.
Phase 5
~1 day
Polish and checks. Keyboard shortcuts, light theme, the checklist below at 375 / 768 / 1024 / 1440 px, docs (docs/web-ui.md, README, changelog).

Estimates are working days for one person and assume no surprises from the slicer.

10. Pre-delivery checklist

Accessibility

  • Text 4.5:1 in dark and light themes, checked separately
  • Visible focus on every control; focus never hidden by the sticky action bar
  • Every action reachable by keyboard, including adding files and reordering plates
  • Colour is never the only signal (icon + word on every badge)
  • Icon-only buttons have accessible names; decorative icons are hidden
  • Errors linked to their fields with aria-describedby

Behaviour and layout

  • No emoji used as icons; pointer cursor on everything clickable
  • Works at 375, 768, 1024 and 1440 px without sideways scrolling; zoom allowed
  • prefers-reduced-motion turns animations off
  • A failed convert keeps all entered values
  • Leaving with unconverted changes asks first
  • Same options in page and command line give identical 3MF files with the same name
  • Files land only in stl/, 3mf/ and gcode/; nothing is overwritten without asking

11. Risks and open decisions

ItemDetailRecommendation
Slicer and its windowThe Creality Print command line shares settings with the app; it should not run while the window is open.Detect the running app and wait with a clear message (section 5) rather than slicing anyway.
Slicer on other OSesThe command line was tested on macOS with 7.3.1 only.Ship slicing as optional; the page converts without it.
Server frameworkFastAPI adds two packages; the standard library alone makes file uploads awkward.FastAPI + Uvicorn, pinned in requirements.txt. Your call.
3D viewthree.js adds about 700 KB of JavaScript; a static thumbnail is free (the converter already renders one).Thumbnail in phase 3, interactive view in phase 4. Your call whether phase 4 is wanted.
RotationThe tilted parts were the real cause of failed prints, but the project rule is never to rotate.Keep the rule; show the tilt warning and the slicer's "Lay on face" hint. Revisit only if you change the rule.
Disk useEvery upload and every variant stays on disk in stl/, 3mf/, gcode/.Show folder sizes in the page; cleaning up stays manual, as today.
ExposureAnything listening on the network could be used by others on the LAN.Bind to 127.0.0.1 only; limit upload size and file count; no shell strings built from file names.
Send to printerPossible through Moonraker on Klipper printers; the Ender-3 V3 SE runs Marlin without it.Out of scope; G-code download only.
